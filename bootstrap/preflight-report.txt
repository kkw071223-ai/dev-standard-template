NEW FINDINGS THE SNAPSHOT COULD NOT SEE

  A. SLEEP IS STILL ARMED - this is now the top blocker.
     Power scheme is "HP Optimized (Modern Standby)".
     STANDBYIDLE = 300 s on AC, 180 s on DC.
     The machine sleeps after five idle minutes. An always-on agent
     cannot exist under that setting. Phase 0-2 has not been applied.

  B. LIDACTION IS HIDDEN IN THIS SCHEME.
     `powercfg /q SCHEME_CURRENT SUB_BUTTONS LIDACTION` prints the
     scheme header and no value, exit 0.

     This corrects the snapshot's own explanation. The snapshot blamed
     a locale bug for the missing power lines. The locale bug was real
     and did throw - but even a correct parser reads nothing here,
     because the setting is hidden in this scheme. Two separate faults
     were stacked, and only one was diagnosed.

     Consequence: `powercfg /setacvalueindex ... LIDACTION 0` may not
     take. Set it, then read it back, and unhide the attribute if the
     read still returns nothing. See design Phase 0-2.

  C. LID POLICY ON BATTERY - EARLIER ADVICE REVERSED.
     The snapshot said lid action should be "do nothing" on both AC and
     DC. That is wrong on DC. A laptop that never sleeps with the lid
     shut and no power will overheat in a bag and drain flat.
     AC = do nothing (always-on). DC = sleep (protect the hardware).
     A job interrupted this way is not lost: Telegram holds the
     instruction for 24 h and the run folder is already frozen.

  D. Confirmed again: S0 is the only sleep state. S1/S2/S3 unsupported,
     hibernate disabled.

NEXT ACTION
  Apply the power policy before anything else. Every later phase
  assumes the machine stays awake.
